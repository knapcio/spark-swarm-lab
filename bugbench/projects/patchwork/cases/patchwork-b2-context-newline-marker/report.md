# Patching adds a newline at the end of a file that has none

Our `.env` file has no newline after its last line. A colleague sent this
patch (generated by git), which only changes the middle line:

```python
from patchwork import PatchSet

patch = PatchSet.parse("--- a/.env\n+++ b/.env\n@@ -1,3 +1,3 @@\n DEBUG=0\n-WORKERS=2\n+WORKERS=4\n PORT=8000\n"
                       "\\ No newline at end of file\n")
print(repr(patch.apply({".env": "DEBUG=0\nWORKERS=2\nPORT=8000"}).tree[".env"]))
```

Expected: `'DEBUG=0\nWORKERS=4\nPORT=8000'` (still no final newline).
Actual: `'DEBUG=0\nWORKERS=4\nPORT=8000\n'`.

The README says the `\ No newline at end of file` marker after a context line
means that both the old and the new file end without a newline. When the
patch changes the last line itself (`-PORT=8000`, marker, `+PORT=9000`,
marker), the result correctly has no final newline, and files that end with a
newline are patched correctly too.
